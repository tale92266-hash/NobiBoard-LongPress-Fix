## Change 1 — Remove the digit from the Q–P long-press popup AND the superscript

**Proven cause (diagnosis §Issue 1):** the digit is a real popup cell — the key's secondary digit. Source is the merge in `res/xml/APKTOOL_DUMMYVAL_0x7f170cae.xml`: the whole file is wrapped in `<if show_secondary_digits="false">`, and its `<else>` block (the fallback for en-IN/en-US) merges a digit key into each Q–P view (e.g. `<merge key_id="@id/0x7f0b117a" view_id="@id/D05" />` for T="5", `0x7f0b11a2` → D06 for Y="6"). `0x7f171211.xml` defines those digit keys (`hint_label="5"` = the superscript, `long_press_data="5"`). The digit ends up as one of the 9 items in the popup `ActionDef.f` list (replacing a blank). `fd2.xml` has ZERO digit tokens.

**Exact change — `res/xml/APKTOOL_DUMMYVAL_0x7f170cae.xml`:**
Removed exactly the **10** `<merge key_id="…" view_id="@id/D01" />` … `view_id="@id/D10" />` lines (decoded lines 286–295) inside the `<else>` block (decoded lines 284–298). Nothing else in the file was touched:
- Language branches (Arabic, Persian, Bengali, etc.) — **untouched** (Arabic branch still has its 10 D01–D10 merges, verified in re-decode).
- `<else>` block kept: `<merge_key_mapping>` wrapper + the `D06_dup` merge (line 296, same "6" digit key merged into the duplicate Y view used by other row-layout variants — NOT the standard en-IN QWERTY row, which uses plain D06 in `0x7f0e009b.xml`).
- The trailing `D11` merge (line 300, outside the `<else>`) — **untouched**.
- File: 303 → 293 lines; parses as well-formed XML.

**Safety check (REQUIRED, passed before rebuilding):**
- All 20 Q–P softkeys (qwertyuiop lower + upper) exist in `fd2.xml` (0x7f170fd2) with 9-token emoji `long_press_data` — verified by regex, none missing, no bad token count.
- All D01–D10 views exist as `SoftKeyView`s in the QWERTY row body `0x7f0e009b.xml` (the body included by the QWERTY def via container `0x7f17000c.xml`) — none missing.
- The Q softkey (0x7f0b185a) is referenced in ~450 def files; the letter keys are defined by fd2 + the def chain, NOT by the cae.xml merge — the merge only ADDS the digit secondary. Removing it cannot remove the letter.
- `fd2.xml` digit tokens `U+003x` = 0 (re-verified).

**Expected result:** Q–P keys show NO superscript digit (Q¹ W² … P⁰ gone) AND the long-press popup shows ONLY the 5 emojis (no digit cell). This matches both of Sam's asks.

## Change 2 — Stop the popup flicker at open

**Proven cause (diagnosis §Issue 2):** the frames prove the popup appears once and stays stable — there is NO on/off/on flicker. The visible "flicker" is the OPEN TRANSITION: the key-preview bubble abruptly switching to the popup, PLUS the stock show animation on the popup layout `res/layout/APKTOOL_DUMMYVAL_0x7f0e0607.xml` (`SilkRectangularPopupView`), which declares `show_animation="@animator/0x7f02005a"` = scaleX 0→1 + scaleY 0→1 + alpha 0→1 (40 ms). Ruled out: two competing animators, c() called twice, the indicator.

**Exact change — `res/layout/APKTOOL_DUMMYVAL_0x7f0e0607.xml`:**
Removed the `show_animation="@animator/APKTOOL_DUMMYVAL_0x7f02005a"` attribute entirely (1 occurrence) from the root `SilkRectangularPopupView` element. `hide_animation="@animator/0x7f020032"` left alone (minimal change; the flicker is on OPEN). File parses as well-formed XML.

**NOT touched:** the indicator animations in `Lqmu.i()` (the 300 ms AnimatorSet that drives the green-circle glide/scale-up — Sam likes that), `Lqmu.o()`/`i()`/`k()`/`c()`, the hook, fd2.xml, the number-row default (still false — manual toggle is the fix), the height ratio 1.2 (classes.dex byte-identical to 853).

**Honest caveat:** the decisive test (does Fix11, which has no hook and the same stock animation, flicker identically?) is still open — Sam has not answered it. The frame evidence says the flicker IS the open transition, so disabling the show animation directly targets it. But if the flicker persists after this build, it is hook-related and the next step is to diagnose the label-walk path, not another blind patch.
