## What changed (Change B ONLY — `Lpud.m` rewrite, ONE dexlib2 pass)

The 861 `Lpud.m` hook body (494 insns) was replaced with a guarded, `TryBlock`-wrapped
implementation (481 insns, 908 units, 16 regs, 1 try block). Substitution semantics are
EXACTLY the same as 858/861: fingerprint token[3] → `emoji_A`…`emoji_Z`, per-column slots
centre {0,3,4,5,6} / left {1,4,5,3,7} / right {1,4,3,5,7}, prefs file
`nobi_longpress_emoji`, canonical order centre,up,down,left,right, `U+200B` spacer,
GUARD-on-any-failure. No Toasts anywhere in the new hook.

1. **Call counter** `Lpud->diagCalls` (new static int): SGET → ADD_INT_LIT8 +1 → SPUT on
   EVERY call, at the very top of the method (before Block E).
2. **Context resolution:** `Lpud->appCtx` first; fallback `ActivityThread.currentApplication()`;
   if the fallback is non-null AND `appCtx` was null, it is `SPUT_OBJECT` into `appCtx`.
   If the Context is STILL null → increment `Lpud->diagNullCtxCount` (new static int) and
   GOTO `:guard` — **NO one-shot lockout**: the counter does NOT gate future calls, and
   Block L' is retried on the next call (same structure as 861).
3. **Array validation:** `[I` length is checked for `== 9` (via `CONST_16 9`) before the
   fingerprint; a null `p1` cannot reach the hook (the fingerprint's `ARRAY_LENGTH` would
   throw and the try/catch routes it to GUARD).
4. **Key identification:** the same 26-way chain on token[3] (`Phase3Tables.LOOKUP_CP`) as
   858/861; non A–Z → GUARD.
5. **Prefs read:** `getSharedPreferences("nobi_longpress_emoji", 0)` → null → GUARD;
   `getString(key, null)` → null or empty (`length() == 0`) → GUARD. The raw string is
   stored in `Lpud->diagPrefs` on success.
6. **Parse & validate all 5 slots BEFORE mutating `p1`:** `split(",", -1)` — 2-arg with
   `CONST_4 -1` (trailing empty tokens are NOT dropped); `parts.length != 5` → GUARD
   (BAD_SPLIT). Per slot: if the part is null/empty (`length() == 0`) OR
   `codePointAt(0) <= 0` → cp = 0x200B (`CONST_16 0x200B`) and the `[Object;` slot gets
   the blank `"\u200B"` string; else cp = `codePointAt(0)`. Both arrays are cloned first
   (`NEW_ARRAY` + `System.arraycopy`) and the ORIGINAL arrays are never mutated.
7. **Apply:** the 5 validated codepoints are written into the cloned `[I` and `[Object;`
   at the Fix11 per-column slots; the 4 corner indices stay 0x200B (they are never written,
   they keep the cloned fd2 values which are already 0x200B). Commit is the two
   `MOVE_OBJECT` instructions (v13←v9, v15←v10).
8. **Diagnostics to `nobi_diag`:** `last_run` = `"run ts=" + currentTimeMillis +
   " calls=" + diagCalls + " nullCtx=" + diagNullCtxCount` (written on EVERY call, BEFORE
   the fingerprint, outside the `diagFirst` gate — the 860 Block-L defect is gone).
   For letter A: `last_a` = `"A cp=1f496 ctx=" + diagCtxSrc + " prefs=" + diagPrefs +
   " outcome=SUB OK|GUARD"`. Keys `last_run` / `last_a` match the editor's Diagnostics
   section. **The P0 Toast, P0 Log, and the `diagFirst` flag-check are REMOVED** (the flag
   field stays in the class, dead but harmless). P1/P2/GUARD `Log.e` calls are KEPT
   (A-key only, they never throw).
9. **Try/catch:** ONE catch-all try block covers the ENTIRE hook — region `[0, 697)`
   (address 0 to the CLEANUP start), handler at address 897. Handler:
   `MOVE_EXCEPTION v0` → `Object.toString()` → `SPUT_OBJECT` into the new static field
   `Lpud->diagLastErr:Ljava/lang/String;` → reset v0/v6 to INT(0) → GOTO `:guard`.
   **The `:guard` is `Lpud.m`'s original instruction 0 semantics** (the clean-up + stock
   body), and the GUARD merge is type-clean (see gates). Any throw in the hook can never
   kill the keyboard-definition load again. The stock body (861 insns 382..443) is copied
   VERBATIM; its internal branch offsets were asserted unchanged.

## Register strategy — (b) SAFER allocation (NO +N remap)

The prompt's +N remap was **NOT** used. Reason: remapping the original `Lpud.m` body by +N
would push its original 4-bit-format instructions above v15 (dexlib2's 4-bit limit) and
break them; rewriting every affected instruction into a wider format is unnecessary risk
for a method whose hook already fits in the existing 16-register layout. Instead,
**strategy (b)**: the original 16-register layout is kept unchanged (params v12..v15,
scratch v0..v11), and the hook uses only low regs v0..v15 in its 4-bit instructions.
The original body's registers are never remapped. Proof of safety:
- **p0..p3 never written in the hook:** the ONLY writes to v12–v15 in the hook region
  [0..365) are the two COMMIT `MOVE_OBJECT`s (insn 324: `MOVE_OBJECT v13, v9`;
  insn 325: `MOVE_OBJECT v15, v10`). v12 (this) and v14 (the `[Lpuz;` param) are never
  written anywhere in the hook. Every `MOVE_RESULT` destination is a proven-dead scratch
  (v0/v1/v6/v8 — the v13 colId lesson from diagnosis-857 is respected; colId lives in v4
  and is never a `MOVE_RESULT` destination).
- **Types of p0..p3 at `:guard` are identical to stock:** the hook leaves v13/v15 as the
  (cloned) arrays, v12 as `this`, v14 untouched; the clean-up resets v3/v6/v7/v8/v11 to
  INT(0) exactly as 861 does, so the stock-body entry types match 861 (proven by
  RegInitCheck 0 + TypeMergeCheck 1 = 1 stock + FieldCheckGen 0).

## Difference vs 862 (for the record)

hook region. 863 REWRITES the hook (no Toasts at all in the new body; richer
diagnostics — `diagCalls`, `diagNullCtxCount`, `diagLastErr`; `split(",", -1)`;
per-slot empty validation to 0x200B; `last_run` with calls/nullCtx counters), with the
SAME catch-all fail-safe. Both remove the 861 killer (Toast on a no-Looper thread).
863's `Lpud.m` is 481 insns (vs 862's 513) because the P0 Toast/Log + flag-check block
was deleted rather than NOP'd.
