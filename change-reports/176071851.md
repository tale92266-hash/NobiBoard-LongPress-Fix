## Bugs found and fixed during this build (record, do not repeat)
1. **Patcher dropped all branch fixups:** `buildBlock()` returned only `b.code`; `patchC()` copied the list into a fresh `B`, losing `labels` + `fixups`, so `fixup()` applied ZERO offsets and every block branch was a self-loop (offset 0). VerifyBranches/RegInitCheck still passed (self-targets are valid boundaries) — only the BranchDump review caught it. Fix: `buildBlock()` returns the `B` itself; `fixup()` now throws on a zero offset.
2. **Plain `GOTO` (10t) out of range:** the 26 chain `GOTO COLSET` jumps up to 226 units; 10t only holds ±127. dexlib2 threw `Invalid code offset: 226`. Fix: chain uses `GOTO_16` (20t); `fixup()` now range-checks every branch format. Block grew 554 → 580 units.
3. **Label at block end:** `LB_DONE` sits at index 317 == `code.size()`; `addr.get(317)` threw IndexOutOfBounds. Fix: a label at end-of-block resolves to `base + total`.
4. **DexBuilder cannot merge DexBacked dexes:** `DexBuilder.internMethod` stores the implementation as-is, so `writeTo` died with `ClassCastException: DexBackedTypeReference cannot be cast to BuilderTypeReference`. Fix: merge via `DexPool.internClass` (the path `DexFileFactory.writeDexFile` itself uses), which converts references properly.
5. **My settings-XML edit mangled a closing tag** (`</androidx.preference.Preference>` became `</androidx.preference>`), caught by aapt2 (`mismatched tag`) and fixed before rebuild.

## What could NOT be verified on-device (Sam's phone test is the only verdict)
1. **The hook's runtime behaviour is UNPROVEN live.** The task asked for the hook to be tested WITHOUT the editor first (manually setting one key's prefs); that was not possible here — there is no device or emulator in this environment, and the editor was built in parallel. What IS proven: the hook's static correctness (all gates above, full branch-target review, full dump review of the 321-instruction block). What is NOT proven: that `getSharedPreferences` returns the editor's file at long-press time, that a custom list actually substitutes and lands on the right plus cells, that label TextViews update, and that no-custom behaviour is exactly Fix11's on a real keyboard open. **If the popup misbehaves on Sam's phone, the first suspect is the hook — and the TypeMergeCheck note above is the second suspect to rule out.**
2. **The Settings-row click path is UNPROVEN.** The `<intent>` Preference is the standard AndroidX mechanism, but whether Gboard's settings fragment lets an intent Preference fire (vs intercepting clicks) can only be shown on-device. There is no launcher-icon fallback (not per spec).
3. **The editor's rendering and prefs round-trip are UNPROVEN** (layout, picker, search, Clear, Reset dialogs, auto-save, dark theme on the Vivo). Only a phone run proves them.
4. **Install-over behaviour from Fix11** (same key, versionCode rise) follows the fixed-key pattern used by every previous build, but was not installed here.
