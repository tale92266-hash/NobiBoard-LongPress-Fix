## Why this build exists (diagnosis-860)

Sam's 860 Diagnostics showed **"No record yet"** for both `Last keyboard load` and
`Last A-key check`, even after force-stop + keyboard open. Diagnosis-860
(`~/workspace/apk-edits/nobiboard-2026-11-11-longpress-defparse-diag3/outputs/diagnosis-860.md`)
proved TWO defects:

1. **Block L (the `last_run` write) only ran on the FIRST `Lpud.m` call per process.**
   BranchDump on shipped 860 `Lpud.m` (498 insns): insn 16 `IF_NEZ -> idx 70` skipped
   insns 17–69 (Block L insns 20–42 AND the P0 Toast/Log) on every call after the
   first. `Lpud.m` is called dozens of times per def-parse (each letter key makes
   TWO calls), but Block L executed at most once.
2. **The Context is null on the first `Lpud.m` call** (deduced: `Lpud.m` IS called
   after force-stop + keyboard open; if v5 were non-null on the first call, `last_run`
   would be written; it is NOT in `nobi_diag`). Def-parse runs on a background
   executor thread very early in process startup, so the first call lands before
   `Lesb.onCreate()` / `ActivityThread.currentApplication()` have set a Context.
   The same null Context makes the substitution hook go to GUARD — one cause, both
   symptoms (no record + no customization). The diagnostic cannot record a null
   Context (writing SharedPreferences requires a Context).

## Fix (a) — Block L moved OUTSIDE the `diagFirst` gate

New `Lpud.m` head (494 insns), assembled from 860's verbatim insns plus ONE fresh
Block L' (identical code to 860's Block L, built by `buildL()` in
`tools/src/CtxFix2Patch.java`):

```
Seg A: 860 insns 0-14   (Block E + CONST_4 v2,-1 sentinel)              [15 insns]
Seg B: fresh Block L'   (every-call last_run write)                    [24 insns]
Seg C: 860 insns 15-18  (flag check/set) + 47-69 (P0 Toast/Log)        [27 insns]
Seg D: 860 insns 70-497 (NOP + fingerprint + rest, verbatim)           [428 insns]
```
Old insns 19–42 (old Block L) and 43–46 (4 NOPs) are DROPPED. New total 494 insns,
917 units (orig 921; delta −4 units = removed 52, added 48 — even, so payload
alignment parity is preserved). **Note:** a method's total unit count need NOT be
even — 860's total was already 921 (odd) and works; only the delta must be even.

The ONLY branch retargeted is insn 16 (`IF_NEZ`): old target 70 → new Seg D start
(new idx 66), offset 50. All other original branch offsets verified UNCHANGED.

New head layout (verified by DumpMethod on the patched dex):

```
 0-13: Block E (Context resolution, unchanged)
   14: CONST_4 v2, -1 (centre-CP sentinel)
15-38: Block L' — IF_EQZ v5 -> 39; build "run ts=<millis>" into v8;
       getSharedPreferences("nobi_diag",0) -> edit().putString("last_run",v8).apply()
       (wide J regs v0/v1 reset to INT(0) after use)
   39: SGET_BOOLEAN v0, diagFirst
   40: IF_NEZ -> 66
41-42: CONST_4 v0,1; SPUT_BOOLEAN v0, diagFirst
43-48: P0 Toast (null-guarded)

   66: NOP (Seg D start)
   67: ARRAY_LENGTH v1, v13 (fingerprint check)
```

On EVERY call the flow is now: Block E → Block L' (write if Context non-null,
skip silently if null, NO flag set) → flag check → (Toast/Log only on first
call) → fingerprint. If the Context is null on the first call, a later call
(when `appCtx` is set) writes `last_run`. The P0 Toast stays gated (once per
process, no spam).

## Fix (b) — Set `appCtx` EARLIER via `Lmxa.attachBaseContext(Context)V`

`Lmxa.attachBaseContext` (4 insns, 2 regs, 0 tries) is the most-derived override
in the chain — verified by probe: `HiltLatinApp` declares only `<init>`;
`Lesb` declares `<init>, a, b, onCreate` (no attachBaseContext); `Lesf` declares
no attachBaseContext and no onCreate; `Lmxa` declares `attachBaseContext(1p)`.
The framework calls it on the Application instance BEFORE `onCreate()`, with
the base Context in v1 (guaranteed non-null).

```
New Lmxa.attachBaseContext (5 insns):
0: SPUT_OBJECT v1, Lpud;->appCtx:Landroid/content/Context;   <- the hook (idx 0)
1: INVOKE_SUPER {v0,v1} Lpdy;->attachBaseContext(Landroid/content/Context;)V
2: CONST_4 v1, 0
3: INVOKE_STATIC {v0,v1} Lvqt;->b(Landroid/content/Context;Z)Z
4: RETURN_VOID
```

v1 is the Context parameter, read at idx 0 BEFORE insn 2 overwrites it with 0.
No branches in the method, so no retargeting. `Lpud.<clinit>` (NEW_INSTANCE
`Lpux`, `SPUT_OBJECT Lpud->q`) is harmless — it creates an empty-byte-array
helper and does not depend on any Context/Application state; it was already
triggered by `Lesb.onCreate()` in 860. `Lesb.onCreate()`'s hook is KEPT
unchanged as a second setter; `currentApplication()` stays the final fallback
in Block E.

## Build-process note (caught by verification, fixed before shipping)

The first `page_align.py` call was run with ONE argument (input only) and
failed with `IndexError` — the script takes `(in_path, out_path)`. The
unsigned APK was signed anyway, and the post-sign `.so` check caught
**7 misaligned** entries (uber-apk-signer's zipalign is 4-byte only, not
16 KB). The build was redone properly: `page_align.py <unsigned> <aligned>`
(0 misaligned on the aligned unsigned APK) → re-signed → final signed APK
verified 0 misaligned. Never trust the sign step to align; always check the
final signed APK.

   - If `ctx=null` → Context still null (then the `attachBaseContext` hook
     did not fire before the first def-parse — report this).
   - If `prefs=null` + `outcome=GUARD` → prefs not found.
   - If `prefs=<value>` + `outcome=GUARD` → split/chain check failed.
   - If "No diagnostic record yet" STILL → the hook never ran or the
     Context is null on EVERY call (the diagnostic's structural blind spot
     remains for an always-null Context — but with `attachBaseContext`
     setting `appCtx` before `onCreate()`, an always-null Context would
     mean the Application itself never had a Context, which cannot happen
     for a running IME).

**Caveat:** live runtime behaviour is unproven on-device — Sam's phone test
is the only verdict. This build is designed so that the outcome (and the
reason, if it fails) is observable in the editor Diagnostics section.
